# V0.4 Roadmap (alpha)

Priority-ordered plan for v0.4-alpha release. Merges V0.3 functional roadmap +
V0.3 performance roadmap into one execution plan. Each item ships as a
perf-tagged commit on the `ai/dev` branch.

---

## Phase 1 — Performance unblockers (shipped)

### 1.1 Per-request log suppression
**Tagged:** `v0.3.0-beta1`
- `src/main.zig`: routing log → `log.debug`
- `lib/zigora_proxy/root.zig`: request completion log → `log.debug`
- `lib/zigora_core/service.zig`: listening log → `log.debug`
- Expected gain: +80-120% debug throughput

### 1.2 Response body streaming
**Tagged:** `v0.4.0-alpha1`
- Removed 8K `resp_buf` stack allocation per request
- Parse response headers first, write immediately to client
- Stream body chunks directly (Content-Length, chunked, or EOF)
- Responses > 8KB no longer truncated

### 1.3 Pre-allocated buffer pool
**Tagged:** `v0.4.0-alpha2`
- New `lib/zigora_core/buffer_pool.zig`: 16-slot atomic-cursor ring
- `PerRequestBuffers { read: [4096], write: [4096], header: [8192] }`
- Service borrows from pool per-request; proxy uses pooled buffers instead of stack
- ~20K less stack allocation per request

### 1.4 Multi-listener parallel accept
**Tagged:** committed
- `Service.startService` spawns N accept futures when built listeners > 1
- Single listener path unchanged (inline accept loop)
- Accept loop extracted as private `acceptLoop` method

## Phase 2 — Functional features (alpha)

### 2.0 Signal handling (SIGTERM/SIGINT)
- **Tagged:** committed
- Server installs `std.posix.sigaction` for SIGTERM + SIGINT
- Global pointer to `Server` for handler callback → calls `shutdown()`
- `runForever` installs handlers before spawning service futures

### 2.1 Request body streaming (POST/PUT)
- **Tagged:** committed
- `BodyHint` struct describes transfer mode (none / content_length / chunked)
- `request.headers` detection for Content-Length
- `proxyToH1` forwards body bytes from client stream to upstream
- Content-Length mode streams directly; chunked mode noted as ponytail skip

### 2.2 Keepalive + ConnectionPool (deferred)
- **Status:** disabled for stability
- `process_new` returns `null` always (reverted from keepalive loop)
- ConnectionPool get/put wired into `proxyToH1` but connection reuse is not active
- **Re-enable when:** downstream conn reuse is tested in multi-threaded benchmarks

## Phase 3 — Pending (v0.4-beta)

Benchmark-derived gaps (2026-08-02, Pingora comparison in `BENCHMARK.md`):
zigora sustains ~19K conn/s but the immediate close-after-response
(`root.zig:326-329`) RSTs responses whenever the client races the close —
~0 req/s vs fast upstreams (211K read errors / 20s), 0.6-95% loss vs slow
ones (bimodal 1K-19K req/s). Pingora on the same box: 8.1K req/s, zero
errors. Items below close that gap, in order.

### 3.1 Downstream keepalive (admit) — DONE (2026-08-02)
- **Root cause found first:** the RST storm was two bugs, not one.
  (a) The upstream-header accumulation loop over-consumed the peeked buffer:
  a fast (HTTP/1.1) upstream delivering headers+body in one read had its body
  silently swallowed into `header_buf` and discarded, so responses were
  header-only and clients saw a truncated body → "0 requests / 211K errors".
  Fixed by stopping consumption at the `\r\n\r\n` terminator, leaving body
  bytes in the reader (`root.zig` header loop).
  (b) close-after-response RST'd when the client raced the close. Interim
  drain (shutdown(.send) + 10ms-timeout reads before close) shipped as 3.1a.
- **3.1b keep-alive loop:** `process_new` now loops per connection — the
  next request head comes from pipelined bytes in the stream reader, else
  from a bounded `receiveTimeout` (50ms) wait into a scratch buffer served
  via `Io.Reader.fixed`. Idle connections close gracefully (no RST).
- `src/main.zig` raises the runtime's default `async_limit` (n_cpu-1 = 7) to
  `.unlimited`; at the default, >7 concurrent keep-alive connections queue
  and latency collapses.
- **Acceptance gate: PASSED** — wrk -t4 -c100 vs node upstream: 53-57K req/s
  (was ~0), read errors 0.0-0.02% (was 100%), timeouts 0 (was 211K errors).
  c8 config: 31K req/s @ 0.5ms median latency.
- **Known residual (std.Io, not proxy code):** Threaded io runs one blocking
  `poll()` per in-flight op, spawning a worker thread per op (305 threads at
  c100). At high connection counts the LIFO run-queue starves long keep-alive
  chains: c100 median latency ~3-7ms with a tail to ~200ms. Clean at ≤8
  conns. Idle timeout 50ms is aggressive for production; tune when a real
  keep-alive lifetime is defined.
- **Residual address (2026-08-02, v0.4.0-alpha6):** swapped the single shared
  `Io.Threaded` for a Pingora-style NoSteal runtime (`zigora_core/runtime.zig`):
  one engine per CPU, engine 0 owns accept, connections dispatched to a random
  engine (`getRandomIo()`). std `Io.Evented` (io_uring) was probed first and
  rejected — it doesn't compile in 0.16.0 (std bug: `Dir.OpenError` missing
  `error.ReadOnlyFileSystem`, refixed upstream post-0.16.0; no 0.16.1 exists).
  Results at c100 hit-path: 62.5-64.6K req/s (was 53-57K), median ~1.5ms (was
  3-7ms), max tail ~103ms (was ~200ms), determinism spread 1.03x (gate < 2x).
  `src/main.zig` no longer tweaks `async_limit`; each engine runs
  `.unlimited`.

### 3.2 Keepalive upstream (PoolNode hot):
- Replace single mutex poolNode with lock-free ArrayQueue (Pingora-style 16-slot hot queue)
- Add idle connection eviction (timeout-based)
- Move pool.Lru to thread-local (per-service) instead of global
- **Prerequisite: liveness check before reuse** — pool currently returns dead
  connections (root.zig ponytail comment); SO_KEEPALIVE or send probe before
  handing a pooled conn back, then re-enable `upstream_pool` in main.zig

### 3.3 Backend health checks (TCP)
- `TcpHealthLoader.check(backend) → Result` — dial with timeout
- Background health check loop (idependently of accept)
- Unhealthy backends removed from active selection set

### 3.4 Structured request logging
- Use that `logging` callback to produce one line per request-finale
- This is: method, path, status, duration, bytes, upstream addr

### 3.5 All-fixture benchmark suite
- `benches/proxy_end_to_end.zig`: 1000 parallel connections, count 200s
- `zig build bench-proxy` step in build.zig
- Corp to baseline: 200 req/s goal (debug), 800+ (release)
- **Determinism gate: PASSED (2026-08-02)** — 3x hit-path runs: c100 62.5/63.8/64.6K
  (1.03x spread), c8 27.6/32.4/33.1K (1.2x spread) — both < 2x gate (was ~19x
  during the RST storm). Byte counters now include the cache-hit path
  (3.6). Remaining: in-repo bench fixture + `zig build bench-proxy` + the
  pingora comparison fixture.
